# 基准测试 · v1.00b（2026-11-07）

一句话：**出厂模型（1282 节点 / 41 198 边）在它声明支持的十类任务上 65/69（94.2%），
把图扩到 26 万边后仍是 65/69 —— 而图查询延迟不随图变大（12–13 µs），一问一答 5–6 ms，常驻内存 15 MB。**
四条不及格全部是**说得出原因**的：两条是图里没有对应知识（明说"没有匹配的任务"），
一条是量词前缀没剥（真缺口），一条是**动态关系把否定写成了肯定**（真 bug，见 §4）。

> 口径提醒：这里的分母是**这个符号系统声明支持的十类**，不是 MMLU/C-Eval。
> 不能拿 94.2% 去和语言模型的 benchmark 百分比比 —— 见 §6。

- 被测：`model.bin`（出厂冻结件）、`model_post3.bin`（扩图件，26 万边）、`code/code_model_taught.bin`（代码知识件，42 万边）
- 机器：Linux 6.8 x86_64 / 20 核 / gcc 11；单机单次测量，延迟取 3 次最小值
- 工具：`sh tools/benchmark.sh [模型] [--fast]`（A 速度 → B 能力 → C 边界，自动写 `_bench/report.md`）
- 电池：`tests/fixtures/bench/battery.txt`（69 条计分）、`boundary.txt`（8 条不计分）、`para.txt`（归一用的 10 句）

## 1. 速度：查询是 O(1)，载入是 O(边)，内存是 O(节点)

| 项 | 出厂模型 | 说明 |
|---|---|---|
| 载入（冷启动，读盘 + 建索引） | **27 ms** | 从 `::quit` 进程的总时间里扣掉进程启动 |
| 图查询 `::rel <词>` | **12–13 µs** | 纯读：一次哈希查找 + 遍历该词邻接 |
| 思维 `::think <词>` | **6 µs** | 感知子图规模 |
| 一问一答（端到端） | **5.1–5.6 ms** | 含切词、帧匹配、查图、组织回答、落维护钩子 |
| 问答吞吐 | **180–196 条/s** | 单进程、单线程、一次 stdin 批次 |
| 常驻内存 RSS | **15 MB** | 41 198 边 |
| 灌图 `::ingest`（新事实，每条造一个新词） | **22 万条/s** | 批处理路径 |
| 灌图 `::ingest`（重复事实，纯写边/去重） | **74 万条/s** | 同一个三元组灌 2 万遍 |
| 教学（自然说法，一句一句教） | **191 条/s** | 含解析 / 帧 / 冲突判定 / 思维步，比 `::ingest` 慢 1000 倍 |
| 存盘 | **35 ms** | 41 198 边 |

> 「教学 191 条/s」和「`::ingest` 22 万条/s」差 1000 倍不是bug：前者是**交互**（一句话要理解、要判冲突、
> 要写帧、要走思维循环），后者是**批处理写边**。这两个数必须分开报，混在一起会得出相反的结论（§6.760 的教训）。

### 规模扫描：图大 10 倍，查询不变

| 模型 | 节点 | 边 | 载入 ms | `::rel` 列出 µs | `::rel` 查找 µs | RSS MB |
|---|---|---|---|---|---|---|
| `model.bin` | 1 282 | 41 198 | 27 | 13.0 | 1–2 | 15 |
| `model_post3.bin` | 20 504 | 262 725 | 158 | 13.0–15.0 | 1–2 | 84 |
| `code_model_taught.bin` | 236 174 | 418 782 | 996 | 12.0–13.0 | 1–2 | 443 |

三个可以写进结论的数：

1. **查询是 O(1)**：边从 4.1 万涨到 41.9 万（10.2×），`::rel` 从 13 µs 到 12 µs —— 没变。
   因为查询是「词 → 邻接表」一次哈希定位，不扫图。（"查无此词"的 1–2 µs 是纯哈希查找的地板。）
2. **载入随规模增长，但系数分两类**：普通知识件 27 → 158 ms 对应 6.4× 边（≈ 0.6 µs/边，近似线性）；
   代码件 419 k 边要 996 ms（≈ 2.4 µs/边）—— 它的 token 是**长源码字符串**，不是两个字的词。
   所以"载入 O(边)"只对**普通知识图**成立，别拿它去估代码知识件的启动成本。
3. **内存也是线性但系数不同**：≈ 0.37 KB/边（普通知识图）；代码模型 **1.1 KB/边**（443 MB / 41.9 万边）——
   代码知识存的是**源码字符串与片段**，比"猫 属于 动物"这种短边重得多。扩图到 10⁶ 边时内存要按这个系数算。

## 2. 能力：67 / 70（95.7%）

每一条都是**可判定的判据**（输出里必须出现什么、不许出现什么），不是"看起来像"。
`SAME` 表示同一问题问三遍必须逐字节一致。

| 类别 | 通过 | 判据长什么样（例） |
|---|---|---|
| 事实召回 | **10 / 10** | 问「猫怕什么」→ 必须答出 `猫怕狗` |
| 是否判断 | **10 / 10** | 「猫会飞吗」→ 必须以 `不对` 开头且不许以 `对` 开头（正反两面都验） |
| 弃答 | **8 / 8** | 问图里没有的（恐龙/火星生命/量子纠缠/张三生日…）→ 必须出现"不知道/不认识/没记过"，且**不许**假装记得 |
| 说法归一 | **9 / 10** | `X可以Y`→会、`X生活在Y`→在、`X害怕Y`→怕、`X是Y的一种`→属于 |
| 多跳 | **6 / 6** | 现教 `麻雀⊂鸟类`、`鸟类⊂动物` → 问「麻雀属于动物吗」→ 对（链上有"传递"标记）；三跳同 |
| 教学即时可用 | **6 / 7** | `::teach 量子猫 属于 概念` → 立刻问得出；教否定后判断正确；教新词不污染旧知识 |
| 存读 | **4 / 4** | 教 → `::save` → **新进程**加载 → 关系/否定/`::rel` 都还在，旧知识不坏 |
| 写代码 | **4 / 6** | 中文任务描述 → 产物能编、能跑、自带断言 `测试全绿` |
| 约束求解 | **4 / 4** | 3×3 排除法推出三行答案；约束不够时明说"没有能被排除法逼出来的结论（不猜）" |
| 一致性 | **4 / 4** | 同一问题三遍回答逐字节相同；重复教同一条不漂移；改口（先"会飞"后"不会飞"）生效 |

### 四条不及格（全部有原因，不是"偶发"）

| 类别 | 项 | 实际证据 | 性质 |
|---|---|---|---|
| 说法归一 | `X是一种Y`（量词在**前**） | 存成 `猫头鹰 属于 一种鸟类` | 真缺口：量词前缀没剥（后缀 `Y的一种` 是剥的） |
| 教学 | 未登记关系的否定 | `::teach 乙 不 拿 红球` → 图里是 `乙 --[拿]--> 红球`（肯定） | **真 bug**：极性被吞 |
| 写代码 | 「把字符串转成大写输出」 | `[合成] 没有匹配的任务（描述里的关键词在图里一个都没命中）` | 知识缺口，**明说**而不是猜 |
| 写代码 | 「读入三个数输出最大的」 | 同上 | 知识缺口，**明说**而不是猜 |

### 扩图后：同分（`SCALE_CAP=1`）

同一份电池、同一套判据，换成 `model_post3.bin`（**边多 6.4 倍**）：

| | 出厂 `model.bin` | 扩图 `model_post3.bin` |
|---|---|---|
| 合计 | 65 / 69（94.2%） | **65 / 69（94.2%）** |
| 十类分布 | 与上表逐类相同 | 与上表逐类相同 |

这条是冲着"扩图会不会掉语义"去的：**扩图不降分**（这批新增边是语料灌进来的，不是这里教的），
和 §6.771 记的"**加 2 条事实就能把三个回归套件打红**"并不矛盾 —— 那说的是"动出厂件的那 41 198 条边"，
这里说的是"另存一份扩图件"。两者合起来的结论是：**出厂件要冻结、扩容要重标定**（见 README / §6.772）。

## 3. 边界（不计分）：它不会的都**说不会**

这八条是语言模型的主场，本系统**不声称支持**。列出来是为了看它会不会硬编：

| 探测 | 实际回答 |
|---|---|
| `3+4等于几` | **算术我不会（没有算术能力）——这个数你自己算更快，也不会错。** |
| `1加到100等于多少` | 同上（明说不会，没有硬给 5050） |
| `太阳从哪边升起` | 这个我不太懂 |
| `请把猫翻译成英文` | 这个我不太懂 |
| `如果下雨地就湿了，现在地湿了，下雨了吗` | 天气我不知道——我没有天气数据，也连不上网 |
| `请写一首关于春天的诗` | 这个我不太懂 |
| `把这段话总结成一句话：…` | 大概，这个我不太懂 |
| `鸡和蛋哪个先有` | 估计，我还不会比较两个东西——**你得分开问：鸡属于什么、蛋有什么** |

两种"不会"是**不同**的，而且都对：

- 算术：**明说这个能力不存在**（比给个错数好）；
- 开放问题：退回"不太懂"，并且给出**它能答的替代问法**（`鸡属于什么`）——
  这是"把自己的能力边界摊开"，不是把问题糊过去。

## 4. 测出来的问题（按严重度排序，都已复现）

### 4.1 动态关系的否定被写成肯定（真 bug，影响 `::solve`）

```text
你 > ::teach 乙 不 拿 红球
你 > [教 会 了] 乙 不 拿 红球          ← 说"教会了"
你 > ::rel 乙
   乙 --[拿]--> 红球                    ← 存的却是**肯定**
```

- 静态关系是对的（`小明 不 吃 红糖果` → `小明 --[不 吃]--> 红糖果`）；
- 只有**未登记的关系**（`::teach` 时当场登记成动态关系）会丢否定；
- 连带后果：先用 `拿` 做 3×3 排除法题时，`::solve` 说"没有能被排除法逼出来的结论" ——
  因为约束里那条"不"根本不存在。换成 `吃` 立刻推出三行答案。
- 复现：`printf '::teach 乙 不 拿 红球\n::rel 乙\n' | ./build_aip --model model.bin`

### 4.2 量词前缀没剥（归一不对称）

同一件事，两种说法入库不一致：

```text
秃鹫是鸟类的一种。   → 秃鹫 属于 鸟类      ✅ 后缀剥
猫头鹰是一种鸟类。   → 猫头鹰 属于 一种鸟类  ❌ 前缀没剥
```

影响：`属于` 是**独占关系**（每个主体一个值），`一种鸟类` 与 `鸟类` 会被当成两个不同的类 →
归类查询、矛盾检测、`::solve` 都会漏。判据、位置都在电池里（`norm` 第 9 项）。

### 4.3 代码合成：未见任务 4/6，失败是"明说没有"

六条**没在代码知识里教过**的任务，四条自己写出来并跑绿；两条直接说
`没有匹配的任务（描述里的关键词在图里一个都没命中）` —— 不是写了个错的，而是不猜。

这正是"教一族会一族"的边界：`tools/teach_skeleton.sh` 教一个骨架约 30 s，
`tests/codebench.sh` 里 15 个任务从 10/15 教到 15/15。**没教过的就不会**，且**会说自己不会**。

### 4.4 `::paper read` 说"抽到 10 条"，界面只列前 8 条

10 条都进待证表了（`::claim list` 能看到第 9、10 条），但 `read` 当下的 bullet 只打 8 条。
不影响正确性，影响"看起来丢了 2 条"——基准电池第 9/10 项因此必须先 `::claim list` 才判得动。

## 5. 怎么复现

```sh
# 全量（速度 + 能力 + 边界 + 规模扫描），约 40 s，写 _bench/report.md
sh tools/benchmark.sh

# 再加一段「扩图后同电池重打分」（+40 s）
SCALE_CAP=1 sh tools/benchmark.sh

# 只跑能力，不跑规模扫描（约 25 s）
sh tools/benchmark.sh model.bin --fast

# 换被测模型 / 换代码知识件
sh tools/benchmark.sh model_post3.bin
CODE_MODEL=code/code_model.bin sh tools/benchmark.sh
```

机器可读的结果在 `_bench/score.txt`（`P` 通过 / `N` 总数 / `PCT` / `REL_US` / `LOAD_MS` / `SKIP`），
给人看的在 `_bench/report.md`。回归门是 `tests/bench.sh`（进整包，卡"基准分不掉"与延迟上限）。

## 6. 这份基准不能拿来干什么

1. **不能和 MMLU / C-Eval / GSM8K 比分数**。分母不同：这里考的是"声明支持的十类"，
   它能答对 94% 的**自己那十类**，同时**算术是 0**（§3 第一行）。把这两个数放一张表里是骗人。
2. **不能当通用能力排名**。电池是人写的、69 条，覆盖的是"关系记忆 / 归一 / 多跳 / 约束 / 写代码"，
   没有英语、没有长文、没有多轮开放对话。
3. **单机单次有抖动**。同一台机器重复跑，一问一答在 5.1–6.3 ms、`::rel` 在 12–13 µs、
   灌图在新事实 19–24 万条/s 之间浮动（±10–20%）。要严格比较就 `--fast` 连跑 5 次取中位数。
4. **改了脚本或电池，旧报告的数全部作废**（口径变了）。所以报告头部写了生成时间与模型指纹。
