# 模型补丁：怎么创建、怎么应用、怎么回滚

> 版本：V0.08a（2026-11-14）。两份实现：**图补丁**（`xe_patch.h`，增量边）与
> **知识补丁**（`code/knowledge/*.triples` + 重建）。别把两者混用。

## 一、两种补丁，先分清

| 类型 | 载体 | 大小 | 适用 |
|---|---|---|---|
| **图补丁** | `xe_patch.h` 的 `XePatch`（一行一条边的增/删）| O(改动)，与图规模无关 | 会话内学到的事实、A/B 实验、回放 |
| **知识补丁** | `code/knowledge/*.triples` + `build_code_model.sh` | O(知识条目) | 代码知识（骨架/运算/片段/概念/词表）|

图补丁**不存整图**：文件头记会话名 + 初始图指纹，装载时先验指纹再顺序重放；
实测 2000 节点的图，2 增 1 删的补丁 **145 字节**，图放大 40 倍大小几乎不变。

## 二、图补丁：创建

```c
#include "ai.h"
#include "xe.h"
#include "xe_patch.h"

AI *ai = ai_new();
/* ……把"初始图"按**确定的方式**建出来（同样输入必须得到同样的图）…… */

char fp[33];
xe_graph_fp(ai, fp, sizeof fp);            /* 记指纹：补丁是给这张图打的 */

XePatch p;
xe_patch_init(&p, "s1", fp);               /* 会话名 + 初始图指纹 */
xe_patch_record_edge(&p, ai, "节点0", "需要", "新目标", 1);   /* + 增一条边（同时写进图）*/
xe_patch_record_edge(&p, ai, "节点0", "需要", "节点1", 0);    /* - 删一条边 */
xe_patch_save(&p, "_t/my.patch");          /* 存盘 */
xe_patch_free(&p);
```

补丁文件长这样（人类可读）：

```
# xe-patch 1
# session s1
# base 2000-2000-8f3c...      ← 初始图指纹：节点数-边数-边哈希
+ 节点0	需要	新目标
- 节点0	需要	节点1
```

## 三、图补丁：应用与回滚

```c
XePatch q;
if (xe_patch_load(&q, "_t/my.patch") != 0) { /* 读失败 */ }

int rc = xe_patch_apply(ai, &q, 0);   /* 0=成功；-2=指纹不符（拒绝）；-1=边/关系找不到 */
if (rc == -2) {
    /* 图不是补丁的基线 ⇒ 默认拒绝；确知无害才强放 */
    xe_patch_apply(ai, &q, 1);        /* force */
}
```

回滚 = 把补丁里的 `+` 当 `-`、`-` 当 `+` 反向重放（或在干净基线上重放旧补丁）。
仓库里的 `tools/xe_patchtest.c` 就是完整例子（建图→记补丁→存→重建→重放→指纹拒绝→force）：

```
gcc -std=c11 -O2 -I. -o build_xe_patchtest tools/xe_patchtest.c -lm
./build_xe_patchtest      # ALL OK
```

## 四、知识补丁（代码知识）：创建流程

1. **改数据**：只动 `code/knowledge/*.triples`（别直接改 `code_model.bin`，它是生成物）：

   | 文件 | 放什么 |
   |---|---|
   | `skeletons.triples` | 任务 → 骨架 → 整段 C |
   | `compose.triples` | 运算 / 配方 / 模板 / 片段 / 打印 |
   | `generalized.triples` | 反统一归纳出的参数化概念（`tools/generalize.py --commit` 写）|
   | `opclass.triples` | 操作类词表（方案 C）|
   | `rewrite.triples` | 说法归一 |
   | `prim.triples` | 带类型的基算子（输入类/输出类/参数槽/操作类）|

2. **重建**：`sh code/build_code_model.sh`
3. **门禁**（缺一不可）：
   - `python3 tools/code_hidden.py` ⇒ **328/328**
   - `AIP_CAPBENCH=1 sh tests/capbench.sh` ⇒ **PASS**
   - `sh tests/all.sh` ⇒ **119 套全过**
4. **提交**：知识文件与生成物分开提交；生成物（`code_model.bin`、`capi.triples`、`c2.triples`）不入库。

写作要点（都是踩过的坑）：
- 关键词按**剥完虚词**的文本写（`全部/所有/里面` 会先被剥掉）；
- `排除` 是**子串**匹配：`排除 二进制` 会误杀 `十二进制`；
- 模式 `{a|b|c}` 最多 **4 个分支**；
- 多个算子抢同一个词 ⇒ 用 `要求/排除/前序无` 让位，而不是继续加关键词。

## 五、发布与回滚纪律

| 场景 | 做法 |
|---|---|
| 单次实验 | 只改 `_t/` 下的模型副本，仓库模型按 sha256 钉住 |
| 采纳知识 | 知识补丁 + 门禁 PASS + 提交；FAIL 就 `git checkout -- code/knowledge` |
| 线上回滚 | 图补丁反向重放；知识补丁回到上一个提交并重建 |
| 版本发布 | 改 `ai.h` 的 `AIP_VERSION` → CHANGELOG → `git tag -a Vx.yz` → push tag → GitHub Release |
