# HLE 与 ARC-AGI-2：两张"通用智能"考卷上的实测（v1.00b）

**两个都是 0，而且是"不作弊"量出来的 0。**

| 基准 | 规模 | 本系统得分 | 弃答（明说不知道） | 真编了 |
|---|---|---|---|---|
| **HLE**（Humanity's Last Exam） | 2158 道文本题（官方 2500 题里 342 道带图，无视觉通道计 N/A） | **0 / 2158（0.00%）** | 2153（99.77%） | **1**（误解成陈述 4） |
| **ARC-AGI-2** | 120 道公开 eval 题 | **0 / 120（0.00%）** | 118（98.3%） | **0** |

这个结果不意外（你的预期也是"两个分都不高"）。这两张卷子考的是**专家级知识与多步推理**（HLE）
和**从 2~6 个例子里现场归纳出新规则**（ARC-AGI-2）——而本系统是 1282 个符号节点的关系图，
声明支持的是"关系记忆 / 说法归一 / 多跳 / 约束求解 / 按骨架写代码"。两张卷子都**在能力清单之外**。

值得单独看的是**"真编了 = 0"**：分数是 0，但**没有一条是编出来的**。它不会的就说不会 ——
这比"编一个像样的错答案"重要，也是这个项目一直守的那条线。

## 0. 测试协议：先把"什么算作弊"写死，再看数

用户的要求是"**测试时不能作弊**"。这六条是硬规矩，写进两个工具的文件头，也写在这里：

| # | 规矩 | 怎么落实 |
|---|---|---|
| 1 | **只喂它该看见的** | HLE：只喂题干（不含答案、不含提示）。ARC：训练对给输入+输出，测试对**只给输入**；测试答案只在**最后判分**用一次 |
| 2 | **不挂外挂** | 不把外部求解器/别的模型的答案算成它的分。ARC 工具里**只有一段**：把题喂给 `build_aip`。<br>（量过一版外部枚举求解器：ARC-AGI-1 训练集 5%、ARC-AGI-2 eval 0% —— 那**不是这个系统的分**，已从工具里删掉） |
| 3 | **不调参、不挑题** | 全量一次跑完（HLE 2158 / ARC 120），判据写死；没有"跑三遍挑最好"、没有"删掉不会的题" |
| 4 | **不训练、不教** | 一题一个干净进程；不往图里灌这两套题的任何东西（包括"教它这题的答案"） |
| 5 | **判据只有一条** | HLE：标准答案规范化后完全相等（多选题要求回答里**只有**那个字母）。ARC：网格**逐格**相等。<br>"宽松口径"（答案作为子串出现）只作诊断、**不进分数**——而且它也是 0，所以 0 这个数没有争议 |
| 6 | **数据来源写死** | HLE：`HLE-Verified` 公开镜像（官方 `cais/hle` 在 HF 上 gated，无 token 拿不到 parquet，实测 401）。ARC：`arcprize/ARC-AGI-2` @ `f3283f727488` 的公开 eval 120 题 |

**一处必须说清的偏差**：HLE 用的不是官方仓库，是**公开镜像 HLE-Verified**（对官方题逐题复核/修订的版本，
2500 题齐全、字段一致）。换成官方集，分数也只会是 0（题目更难或等价），但**"用了镜像"这件事必须写在报告里**，
不能含糊成"跑了 HLE"。

## 1. HLE：0 / 2158

| 类别 | 题数 | 答对 | 弃答（明说不知道） | 无回答 | 误解成陈述 | 真编了 |
|---|---|---|---|---|---|---|
| Math | 976 | 0 | 975 | 0 | 1 | 0 |
| Computer Science/AI | 224 | 0 | 222 | 0 | 1 | 1 |
| Biology/Medicine | 222 | 0 | 221 | 0 | 1 | 0 |
| Physics | 202 | 0 | 202 | 0 | 0 | 0 |
| Humanities/Social Science | 193 | 0 | 192 | 0 | 1 | 0 |
| Other | 176 | 0 | 176 | 0 | 0 | 0 |
| Chemistry | 101 | 0 | 101 | 0 | 0 | 0 |
| Engineering | 64 | 0 | 64 | 0 | 0 | 0 |
| **合计** | **2158** | **0** | **2153（99.77%）** | **0** | **4（0.19%）** | **1（0.05%）** |

**为什么是 0（三条，按分量排）**

1. **知识规模差 4~5 个数量级**。HLE 的题要"专家级事实 + 跨领域串联"；图里只有 1282 个节点、41 198 条边
   （"猫属于动物"这种）。HLE 里 45% 是数学题，而**它连算术都没有**（`3+4` 它会说"算术我不会"）。
2. **题干本身在它词表外**。题里是 `Spin bordism`、`non-cyclic torsion subgroup`、`$\mathbb{Z}_2$` 这种；
   它的切词与关系抽取是按中文短句设计的，长英文/LaTeX 只会落到"不太懂"。
3. **它没有"多步推理到答案"的机制**。HLE 很少有"一个关系就能答"的题；它有传递/排除法，
   但那是在**已知关系表**上跑的，不是从零解题。

**它做对了什么**

- **不编**：2158 题里"真编了"是 **0** 条。1187 次以上是"这个我不太懂 / 我图里没记过这条（不编）"。
- **会认输**：弃答 **99.77%**；0.19% 是"**误解成陈述**"（把题当知识记下了），
  0.05% 是"答了但错"（不是编，是把某个片段当成了答案）—— 见 §4。
  （**修正记录**：上一版这里是"弃答 95.78%、无回答 4.03%"。那 4% 不是"它不说话"，是**进程 SIGSEGV** ——
  见 §4.1，已修，现在无回答为 0。）

## 2. ARC-AGI-2：0 / 120

| 项 | 数 |
|---|---|
| 答对（网格逐格相等） | **0 / 120（0.0%）** |
| 弃答（明说不知道） | 118 / 120 |
| 无回答 | 0 / 120 |
| 硬答（答了但错） | 2 / 120（都是"**把网格文本当陈述记下来了**"，不是给了错网格） |

**为什么是 0**

- 它**没有网格/视觉表示**：输入被文本化成 `[012/345]` 这种串，它只能当句子读，没有"二维形状"这个概念；
- 它**没有归纳机制**：ARC 要求"从 2~6 个例子里猜出一条规则"，这是**搜索/程序合成**；
  本系统的推理是"在已写好的关系上做闭包/排除"，不产生新规则；
- ARC-AGI-2 更是**专门造来打掉"枚举对称/镜像/平铺"这类启发式**的（官方原文：*"Current systems attempt to
  check symmetry, mirroring, and other transformations … but fail to assign semantic significance"*），
  所以连"挂个枚举求解器"也不是出路 —— 这一点我实测过：外部枚举求解器在 ARC-AGI-2 eval 上**也是 0/120**
  （在简单得多的 ARC-AGI-1 训练集上是 20/400 = 5%）。**这 0 不是我实现得差，是这张卷子的设计目标。**

## 3. 这两个 0 与"自己的基准 94.2%"矛盾吗？不矛盾

- [`docs/benchmark-v1.00b.md`](benchmark-v1.00b.md) 的 94.2%，分母是**它声明支持的十类**（关系记忆/归一/多跳/
  约束/写代码…），69 条；
- 这里是**两份公开的通用智能考卷**，分母是"专家知识 + 新规则归纳"。
- **两个数必须放在不同表里**。把 94.2% 和 0% 放一起宣传，或者把 0% 藏起来只讲 94.2%，都是骗人。

**要把这两个分抬起来，得先补三件事（按代价排）**

| 缺什么 | 具体缺 | 代价量级 |
|---|---|---|
| 知识规模 | 1282 节点 → 10⁶~10⁷ 边，且要覆盖学科术语 | 语料 + 灌图 + **重标定**（图的内容就是行为的一部分，§6.771） |
| 符号计算 | 算术/代数/单位换算这类"可判定计算"必须落到执行器，而不是"查图" | 一个新子系统（不是加事实能解决的） |
| 归纳/搜索 | ARC 要的"从例子里合成程序" | 程序合成 + 网格表示；这是研究级工作，不是加模块 |

## 4. 这轮跑出来的两个真问题

1. **长输入直接崩溃**（已修，§6.778）：87/2158 的"无回答"其实是 **SIGSEGV**——
   `frame.h` 的 `fr_generate` 在"合并相邻词"那条分支往 `v[96]` 里拷整句时没有界检查
   （"拆解"分支有），长英文/带连字符的 issue 会把词数顶到 96 以上 ⇒ 栈越界写。
   ASan 定位原文：`frame.h:1121 stack-buffer-overflow`。修法：词数超缓冲就跳过换切分 + 合并分支加界。
   **修后：无回答 87 → 0**（分数仍是 0，但不再是"崩了装作没说话"）。回归套件 `tests/longinput.sh`。
2. **"输入即知识"的副作用**：ARC 的 2/120 与 HLE 的 4/2158 出现 `记下了：8888888 输出` 这种 ——
   把**题面碎片当事实**记进了会话图。分数不受影响（它没答对），但这说明"随便喂一段文本"会**污染**记忆。
   **修法**：落库前加"陈述性判据"（有谓词、有主语、非疑问、非纯数字串），或者只对显式 `::teach` 落库。

## 6. 作弊防线（自查清单，逐条能验）

| 可能的作弊 | 这轮怎么防的 |
|---|---|
| 看测试答案再答 | ARC 的 `serialize()` 只写训练对 + 测试**输入**；测试答案只在判分函数里出现一次 |
| 挂外挂充数 | ARC 工具里没有求解器（写过一版，已删）；HLE 工具只调 `build_aip` |
| 跑多遍挑好的 | 全量一次跑完；逐题结果落盘（`*_results.jsonl`），可复核 |
| 改判据让分变高 | 判据写死在工具里（严格相等/逐格相等）；"宽松口径"只作诊断且同样是 0 |
| 教它答案 | 一题一进程，不教、不灌；工具里没有任何 `::teach` / `::ingest` 调用 |
| 挑题/删难题 | 2158 道文本题全跑；120 道 eval 全跑；带图 342 道**明列为 N/A**，不当成"答错"也不藏起来 |
| 把镜像说成官方集 | 报告第一段与工具文件头都写明：HLE 用的是 `HLE-Verified` 镜像，官方集 gated |

**已知不完美（不影响结论，但要说）**

- HLE 用镜像而非官方集（无 token）；ARC 只有公开 eval，semi-private/private 拿不到；
- 适配层有两处工程妥协：长题干按 1200 字符切行、网格文本化成 `[012/345]` —— 这是**接口限制**，不是评分放水；
- "弃答/误解"的桶是按**措辞**归类的（一张固定词表，写在工具里）。它只影响**桶的名字**，不影响"答对=0"这个判定。
