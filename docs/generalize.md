# 举一反三：谓词代数（数据驱动的 R1/R3/R4）

> 一句话：**规则本来就有，缺的是"属性"这层数据。** 把属性从 C 里搬进 `relprops.txt` 之后，
> 教一条事实就能按属性往回收／往深推；`AIP_NOALG=1` 关表，这份能力当场消失（消融判据）。

## 0. 为什么是"举一反三"而不是"多背几条"

`rel.h` 里的推理规则有四条（R1 传递、R2 继承、R3 对称、R4 逆关系），但**属性写死在
`AI_RELS[]` 里**，只覆盖十来个核心关系。`relations.txt` 教进来的动态谓语（`认识`/`包含`/
`一样`…）一条属性都没有 —— 于是：

```
教：甲 认识 乙          教：丙 包含 丁 ；丁 包含 戊
问：乙 认识 甲 吗        问：丙 包含 戊 吗
答：图里没记过（不编）    答：图里没记过（不编）      ← 修之前
```

这不是"知识不够"，是**属性不是数据**。修完之后：

```
教：甲 认识 乙        → 乙 -[认识·对称]-> 甲
教：甲 一样 乙        → 乙 -[一样·对称]-> 甲     ← 表里没有「一样」，它从同义组「相同」借到属性
教：丙 包含 丁；丁 包含 戊 → 丙 -[包含·传递]-> 丁 ；丁 -[包含]-> 戊
```

一条示范（一），三种方向（反）：**反向、更长的链、同义词**。

## 1. 机制（改了什么）

| 文件 | 改动 | 判据 |
|---|---|---|
| `rel.h` | `relprops.txt` 装载器（`prop/syn`，行内 `#` 出处）；`relprops_of()` = 核心声明 ∪ 数据表 ∪ 同义组（**一跳**）；R1/R3/R4 从 `rd->trans/…` 改为读属性；新增 `::rel prop [词]` | `tests/generalize.sh` |
| `rel.h` | R4 逆关系：`inv` 现在是**名字**，现查 id（逆谓词可能还没进图 ⇒ 查不到就不推，不偷偷登记） | `tests/generalize.sh` |
| `derive.h` | 验证器 `der_verify` 的合法性判据从 `rel_by_id(goal)` 改为 `relprops_of(goal)` | 修之前：求解器推对了、答复层却因 `gaps>0` 拒绝下断言 |
| `main.c` / `model_io.h` | 四个装载收尾点补 `relprops_load()`（与 `relations_load` 同序） | 读盘/训练后属性都还在 |
| `rel.h` | `AIP_NOALG=1` 整张表不装载 | 消融：增益必须只在开表时出现 |

**一处踩过的坑（写下来防再犯）**：合法性要按**被问的那个关系**判，不能按"这一跳的关系"判 ——
继承链的一跳写的是 `属于`（它自己 `inherit=0`），合法性得对着目标关系（`有`）看。
按跳判会让 `猫 有 毛` 退回「我不太确定」（实测）。

## 2. 蒸馏协议（`tools/distill_relprop.py`）

目标：让本地模型只输出**谓词怎么推广**，不输出任何具体实体的答案。

```
池检查（只收模型词池里真有的谓词：批量 ::rel，确定性）
  → 每个教师 × 双跑（temp 0.2 / 0.8）
  → 逐字段**全票一致**才保留（agreement gate）
  → 确定性过滤：inv/syn 必须在池里、inv≠自己、逆关系不许一对多
  → relprops.txt（带出处注释）
```

多教师是为了**去掉单个模型的口头禅**（不同模型犯的错不一样）。用法：

```sh
python3 tools/distill_relprop.py --out relprops.txt \
  --teacher "http://127.0.0.1:18321/v1|<key>|qwen3-0.6b" \
  --teacher "http://127.0.0.1:18322/v1|<key>|qwen2.5-coder-1.5b"
```

原始输出落在 `_bench/distill/<模型>_t<temp>.json`（可复查，不在 git 里）。

## 3. **负结果：本地小模型给出的属性不可信**（本轮实测）

用 `qwen3-0.6b`（快）当教师，双跑交集过滤之后仍然是这样一张表（节选）：

```
prop 了解 sym        ← 错：A 了解 B ⇏ B 了解 A
prop 像   sym        ← 错
prop 保护 trans      ← 错
prop 怕   trans      ← 错
prop 喜欢 sym        ← 错
syn  讨厌 喜欢       ← 错得离谱
```

这张只有 14 条属性的表里，**只有 1 条是对的**（`属于 trans` —— 而它本来就是 `AI_RELS` 声明的核心关系）。
换 `qwen2.5-coder-3b` 抽 6 个谓词人工核对：`认识`✓ `包含`✓ `怕`✓ `保护`✗ `像`✗ `了解`✗（**3/6**）。
再试「请反驳这个断言」的自我反驳提示词：

```
断言：A 喜欢 B 当且仅当 B 喜欢 A。
qwen3-0.6b   → {"ok": true}
coder-1.5b   → {"ok": true}
```

两个模型都认为「喜欢」对称。**结论：这类语义属性上的错误是系统性的，不是采样噪声；
0.6B/1.5B/3B 都当不了这个教师。** 所以 `relprops.txt` **不收录模型产物**，只收两类有出处的条目：

```
prop 包含 trans        # [代码] 包含 = 属于⁻¹（AI_RELS 声明），属于 声明了 trans
prop 认识 sym          # [常识] A 认识 B ⇔ B 认识 A
prop 相同 sym          # [常识]
syn 一样 相同          # [常识] 同义 ⇒ 代数同
```

这不是"蒸馏失败就算了"：管线留着，教师换强的（`--teacher` 直接指过去）就能用；
而且**教师提假设、证据来裁决**这条纪律，比"让 0.6B 说了算"重要得多。

## 4. 判据：泛化台（题目自动生成，不手写）

`tools/gen_generalize.py` 从三处独立来源出题（实体名现场新造：甲/乙/丙/丁/戊）：

| 族 | 来源 | 量的是什么 |
|---|---|---|
| `ctl` | `relations.txt` 的属于链/上位继承 | 老能力不能退（真值来自图） |
| `sym` / `trans` / `syn` | `relprops.txt` | **引擎有没有按表外推**（机制） |
| `neg` | 词池里有、表里没有的谓词（追/讨厌/知道/相信） | 不许乱推广（反向问句不能答"对"） |

`tests/generalize.sh` **自带消融**：同一份题、同一个二进制再跑一遍 `AIP_NOALG=1`。
三条同时成立才算 PASS —— ① 开表新族全绿；② 关表新族至少掉一半；③ `ctl` 两遍全绿、`neg` 两遍不乱推。

实测（`sh tests/generalize.sh`）：

```
开表  17/17    关表  12/17
  sym    2/2  →  0/2
  trans  2/2  →  0/2
  syn    1/1  →  0/1
  ctl   10/10 → 10/10
  neg    2/2  →  2/2
```

增量 5 条全部来自谓词代数，且**关表就没了** —— 因果链闭合。

## 5. 局限（写清楚，别假装没有）

1. **表很小**（3 条属性 + 1 条同义）。可用的属性知识从哪来还没解决：小模型不可信，
   大模型（7B）在本机太慢（用户明确要求换小模型），人工写又违背"蒸馏"的初衷。
2. **没有运行时教学**：现在只能改 `relprops.txt` 生效（`::rel prop` 只能看）。下一步是
   `::rel prop <词> sym|trans|inv <词>` —— 一行教会一个谓词，和 `::law` 一个形状。
3. **同义只走一跳**：A≈B、B≈C 不会让 A 拿到 C 的属性（故意的：一条错边别染一片）。
4. **逆关系对称**（`卖 inv 买` ⇒ `买 inv 卖`）是**近似**：真汉语里「卖」是三方谓词，
   二place 只是简化。所以表里目前一条 `inv` 都没有 —— 宁可空着。
5. 判据里的 `sym/trans/syn` 族量的是**机制**，不是"属性对不对"；属性的真假由出处（代码/常识）
   和 `neg` 对照兜着。这一点必须和分数一起说，不然就是把机制分当知识分。
